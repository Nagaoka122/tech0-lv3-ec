# 定番衣類の買い替え支援ECアプリ

スクール個人課題 Lv3 の提出物です。GUのECサイトを題材に、要求定義・要件定義・設計を行いました。

## 取り組んだ課題

**買うものが決まっている買い物なのに、毎回ゼロから探し直している。**

仕事で着るTシャツとYシャツを、毎年ほぼ同じ時期に、ほぼ同じものへ買い替えています。買うものも
買う時期も決まっているのに、毎回そのたびに検索し、去年と同じカラー・サイズを思い出しながら
選び直し、複数種類を別々に注文しています。

一般的なECサイトは「まだ買うものが決まっていない人が、商品を見つけて選ぶ」ことを前提に
設計されています。検索も比較もそのための機能です。しかし買い替えでは、それらは**不要な作業**
です。

| | はじめて買う場合 | 毎年の買い替え |
|---|---|---|
| 買うもの | 決まっていない | すでに決まっている |
| 必要な支援 | 見つける・選ぶ・比べる | **探す手間をなくす** |
| 買う時期 | 思い立ったとき | **毎年ほぼ同じ時期** |

そして、**毎年買うということは、毎年捨てるということです。** 買い替えは「新しいものを買う」
ことと「古いものを手放す」ことの対で成立しているのに、ECサイトが扱っているのは前半だけです。

## 提案する仕組み

**毎年買うものを定番セットとしてまとめ、買い替えの時期が来たら知らせ、確認するだけでまとめて
注文できるようにします。** あわせて、着なくなった衣類を返送すると翌年使える割引券が届きます。

```
購入履歴 ──▶ 定番セットに登録 ──▶ 履歴から周期を推定
                                        │
                    予定日の14日前 ──▶ 通知
                                        │
                        確認・修正できる画面 ──▶ まとめて1件の注文
                                        │
                去年の分を返送 ──▶ 受領 ──▶ 翌年使える割引券
                                                  └──▶ 翌年の注文で自動提示
```

設計上こだわった点が4つあります。

**1. 買い替え時期は本人に設定させず、購入履歴から推定する**
本人が周期を意識していなくても機能させるためです。ただし推定は外れるので、**根拠（前回いつ
買ったか、推定した周期）を示し、本人が上書きできる**ようにしています。

**2. 完全な自動注文にはしない**
通知から注文までの間に、必ず確認・修正できる画面を挟みます。衣類はサイズや必要枚数が年に
よって変わるため、本人の確認なしに確定させるべきではないと判断しました。

**3. まとめ買いは定番セット単位に限る**
汎用のカートは作りません。任意の組み合わせを扱うと在庫確保と部分欠品の設計が必要になります。
セット単位に限れば、「全品目そろって注文が成立する」という単純な規則で済みます。

**4. 下取りの割引は「その場」ではなく「翌年」に効かせる**
返送を待ってから買うと、「時期が来たらすぐ買える」という中心価値を自分で壊します。かといって
先に割引だけ渡すと、返送されないリスクを負います。**受領してから翌年用の券を発行する**ことで
両方を避けました。買い替えが1年周期なので、券の周期も1年で噛み合います。

このため**利用開始の初年度は割引が働きません**。返送する対象がまだないためです。定番を
繰り返し買う人に向けた仕組みとして、これは受け入れています。

## 作る範囲

| # | 機能 | 内容 |
|---|---|---|
| 1 | ログイン | 会員登録、ログイン、ログアウト |
| 2 | 商品表示 | 商品一覧・検索、詳細でのカラー・サイズ選択 |
| 3 | 購入 | 選んだSKUの購入（模擬決済） |
| 4 | 購入履歴と定番セット | 履歴一覧、セット登録、周期の推定、リマインド、セット注文 |
| 5 | 下取りと割引券 | 履歴から返す品目を選んで申込、受領で割引券を発行、注文時に適用 |
| 裏 | 日次バッチ | 周期の推定、リマインドの生成、期限切れ券の失効 |

自動注文・汎用カート・配送・店舗受け取り・POS接続・実決済は今回作りません。返送の物流
（集荷手配、配送ラベル、追跡）も対象外で、申込・状態・割引の発行までを扱います。

## 決めた数値

各数値について「決めた数字／何と何を天秤にかけたか／動かすと何が悪くなるか／一緒に決まる数字」
を記載しています。

| 数値 | 値 | 天秤にかけたもの |
|---|---|---|
| 周期の推定に必要な最小購入回数 | 2回 | 推定の確からしさ ⇔ 機能が使えるようになるまでの待ち時間 |
| 周期のばらつき許容 | ±45日 | 定期的な買い替えを取りこぼさないこと ⇔ 定期的でない購入を誤認しないこと |
| リマインドのタイミング | 予定日の14日前 | 配送を待つ余裕の確保 ⇔ 早すぎて通知が無視されること |
| 定番セットの上限 | 10品目・合計20点 | まとめ買いの利便性 ⇔ 確認画面が長くなり確認が形骸化すること |
| 購入履歴の遡及期間 | 3年 | 買い替えサイクルのカバー ⇔ 表示の煩雑さと保持コスト |
| 割引券の有効期限 | 15か月 | 買い替え周期のばらつきの吸収 ⇔ 会計上の負債と値引き原資の読みにくさ |
| 下取り1点あたりの割引 | 200円（上限10点） | 返送を促す魅力 ⇔ 回収・選別コストと粗利 |
| 1注文に使える割引券 | 1枚 | 使いやすさ ⇔ 割引の集中と原資の偏り |

**割引券の有効期限は、他の数値から導出しています。** 推定周期365日にばらつき許容±45日
（上表2行目）を足すと、次回購入は最大410日後になりえます。12か月（365日）にすると、買う
時期が例年より遅れた人の券が必ず失効する。これを超える最小の月単位が15か月です。
