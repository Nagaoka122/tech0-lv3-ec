# 定番商品リピート購入ECアプリ

スクール個人課題 Lv3 の提出物です。GUのECサイトを題材に、要求定義・要件定義・設計を行いました。

## 取り組んだ課題

**去年と同じものをまた買いたいのに、まだ売っているのか分からない。**

仕事用のポロシャツや無地のTシャツを毎年買い替えるとき、去年と同じ商品を買い直したいのですが、
まだ販売しているのかが分かりません。「在庫なし」と表示されても、**待てば入荷するのか、もう
入荷しないのか**が判断できず、待ち続けるか諦めるかを決められませんでした。

## 設計の中心

「買えない」状態には原因の異なる2種類があり、**顧客が取るべき行動は正反対**です。

| 状態 | 原因 | 顧客が取るべき行動 |
|---|---|---|
| 品切れ | 一時的に在庫が切れている | 待つ |
| 終売 | 販売そのものが終了した | 待っても無駄。別の商品を探す |

しかし画面上はどちらも「在庫なし」で、区別がつきません。**この2つを分ける判断**を設計の中心に
置き、「連続何日間在庫が0なら終売とみなすか」という閾値を決めました。

判定の根拠は在庫の日次スナップショットです。**記録を始める前の期間は後から復元できない**ため、
今回の設計に含めています。

## 作る範囲

| # | 機能 | 内容 |
|---|---|---|
| 1 | ログイン | 会員登録、ログイン、ログアウト |
| 2 | 商品表示 | 商品一覧・検索、詳細でのカラー・サイズ選択 |
| 3 | 購入 | 選んだSKUの購入（模擬決済） |
| 4 | 購入履歴 | 履歴の一覧、販売状態の表示、履歴からの再購入 |
| 裏 | POS販売の受け口 | 店頭販売を在庫へ反映する接続口 |
| 裏 | 日次バッチ | 在庫の日次記録と終売判定 |

配送・店舗受け取り・取り寄せ・再入荷通知・カート・実決済は今回作りません。
POS本体の改修も行わず、EC側の受け口までとしています。

## 決めた数値

各数値について「決めた数字／何と何を天秤にかけたか／動かすと何が悪くなるか／一緒に決まる数字」
を記載しています。

| 数値 | 値 | 天秤にかけたもの |
|---|---|---|
| 終売とみなす連続在庫0日数 | 30日 | 早すぎる見切りによる販売機会の損失 ⇔ 入荷しない商品を待たせ続けることによる離反 |
| 購入履歴の遡及期間 | 3年 | 買い替えサイクルのカバー ⇔ 表示の煩雑さと保持コスト |
| 販売状態の判定単位 | SKU（品番×カラー×サイズ） | 判定の正確さ ⇔「販売中」と表示される件数 |
| 在庫スナップショット取得間隔 | 1日1回 | 終売判定の精度 ⇔ データ蓄積量 |
| 1注文の数量上限 | 10点 | まとめ買いの利便性 ⇔ 在庫を枯渇させることによる他の顧客の機会損失 |
